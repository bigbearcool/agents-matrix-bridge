# 修复 plugin-ui ui/initialize 握手超时（matrix-bridge 面板全面 MCP 化）

## Context

ZCode 打开 Matrix Bot 面板报 `plugin-ui: ui/initialize handshake timed out`。根因：宿主把 `ui://matrix-bridge/panel.html`（`text/html;profile=mcp-app`）装入 webview 后等待页面用官方 `@modelcontextprotocol/ext-apps` SDK 完成 `ui/initialize` 握手，但这份 console 是从 antigravity sidecar 移植的（依赖宿主注入的 `window.sidecar`，ZCode 里不存在），只有直连守护进程 HTTP 的逻辑，从不握手 → 宿主超时。

大熊已定：**顺带全面 MCP 化**（面板数据改走 `app.callServerTool`，11 个 MCP 工具已与 HTTP 端点 1:1 对齐）+ **修好立即部署**。

## 改动清单

### 1. 新增构建脚手架 `ZCODE/tools/console-build/`（在插件安装树外）
- `package.json`：devDeps 锁定 `esbuild` + `@modelcontextprotocol/ext-apps@2.0.4`（npm 现为 2.0.4，单一依赖 @standard-schema/spec）
- `connector.src.js`：创建官方 `App` → `app.connect()`，成功后挂 `window.__mcpApp`；无论成败落定 `window.__mcpAppReady`；`onhostcontextchanged` 把宿主主题变量翻译成 app.js 已监听的 `{type:'theme-change', payload:{cssVariables}}` postMessage（复用 app.js:71-80 现有监听，零改动实现亮暗跟随）
- `build.mjs`：esbuild 打包为 **IIFE、minify**（内联 `<script>` 不能是 ESM），产物输出到 `plugins/matrix-bridge/engine/console/vendor/mcp-app-connector.js`，产物提交进仓库
- 动手时先读安装包内 types/quickstart 核对 `App` 构造与 `callServerTool` 返回形状（`content[0].text` + `isError`）

### 2. `ZCODE/plugins/matrix-bridge/mcp/server.mjs` — `buildPanelHtml()`
- 现在把 `<script src="/preload.js"></script>` 置空（server.mjs:32）；改为在此接缝内联 vendor 连接器 bundle（置于 app.js 之前）。浏览器直开模式不受影响（main.mjs:1831 的 preload 桩保持不动）

### 3. `engine/console/app.js`
- `init()`（app.js:1246）开头：`if (window.__mcpAppReady) await window.__mcpAppReady;`
- `api()`（app.js:157）增加 MCP 分发层：`window.__mcpApp` 存在时把 (path, method, body) 映射到工具调用并解包 `content[0].text` 的 JSON，`isError` 抛错；映射表：
  - `GET /api/status`→`matrix_bridge_status`；`GET /api/config`→`matrix_bridge_config{action:'get'}`；`POST /api/config`→`{action:'set', patch:body}`；`POST /api/login`→`matrix_bridge_login`；`POST /api/verify-token`→`matrix_bridge_token`；`POST /api/logout`→`matrix_bridge_logout`；`GET /api/rooms`→`matrix_bridge_rooms`；`POST /api/rooms/update`→`matrix_bridge_room_update{room_id:body.id,...}`；`GET /api/fs/browse`→`matrix_bridge_fs_browse{path}`；`GET /api/fs/search`→`matrix_bridge_fs_search{q}`；`GET /api/logs`→`matrix_bridge_logs`；`POST /api/daemon`→`matrix_bridge_daemon{action}`
  - 注意对齐响应形状差异（尤其 daemon 工具的 `{daemon_output}` 包装 vs HTTP 端点原形状，实现时对照 main.mjs 与面板调用点）
- 浏览器直开（无 `__mcpApp`）走原 fetch 分支，行为不变

### 4. 版本与文档
- `.zcode-plugin/plugin.json` 与 `plugins/marketplace.json`：0.2.0 → 0.2.1
- `deploy.sh`：面板 HTML 断言追加 `__mcpApp` 存在（确认连接器已内联）
- `README.md` §8：补充连接器重建步骤（改 connector 后跑 `tools/console-build`）
